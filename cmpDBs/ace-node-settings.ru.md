# ACE: настройки нод, от которых зависит результат сравнения

Хэш строки в ACE считается по тексту: `sha256(convert_to(ROW(...)::text, 'UTF8'))`, первые 8 байт, numeric-колонки обёрнуты в `trim_scale()` (`RowHashExpr`, `db/queries/queries.go`). Поэтому всё, что меняет текстовый вывод значения или порядок ключей, может дать ложное расхождение.

Значения в группе 1 совпадают с `deparseSettings` в `internal/consistency/schema/collect.go`. Список должен быть один, общий для schema-diff и для путей данных (table-diff, mtree, CDC).

## Группа 1. GUC сессии: фиксировать во всех соединениях ACE

Задавать через startup packet (`RuntimeParams` в `applyRuntimeParams`, `internal/infra/db/auth.go`), включая replication-соединение CDC: pgoutput переводит значения в текст внутри walsender, с GUC его сессии.

Сейчас для путей данных эти параметры **не фиксируются**: `applyRuntimeParams` ставит только `statement_timeout`, keepalive и `application_name`.

### `TimeZone = 'UTC'`

- **Влияет на:** вывод `timestamptz`. На `timestamp`, `date`, `timetz` не влияет (у `timetz` смещение хранится в значении).
- **Почему UTC:** у UTC нет правил перехода на летнее время. Для именованной зоны (`Europe/Berlin`) вывод зависит от версии tzdata на ноде: при `--with-system-tzdata` и разных пакетах ОС одинаковый `TimeZone` всё равно может дать разный текст для дат, у которых меняли правила.

### `DateStyle = 'ISO, YMD'`

- **Влияет на:** вывод `date`, `timestamp`, `timestamptz` (форматы ISO / SQL / Postgres / German). Вторая часть (`YMD` / `DMY` / `MDY`) на вывод ISO не влияет, но определяет разбор неоднозначного ввода.
- **Почему ISO:** единственный однозначный формат; pg_dump использует его же. Для repair: значения, переданные обратно текстом, будут в ISO и разберутся одинаково при любом порядке. `YMD` — для согласованности с collect.go.

### `IntervalStyle = 'postgres'`

- **Влияет на:** вывод `interval` (`1 day 02:00:00`, `P1DT2H`, `+1 +2:00:00` и т.д.).
- **Почему postgres:** значение по умолчанию, pg_dump задаёт его же. Ввод в этом формате понимается при любом `IntervalStyle`, поэтому repair безопасен. Все четыре стиля без потерь, выбор — согласие с pg_dump.

### `bytea_output = 'hex'`

- **Влияет на:** вывод `bytea` (`\x0102` или escape-формат).
- **Почему hex:** значение по умолчанию с 9.0; быстрее и с предсказуемым размером (2 символа на байт). Escape для двоичных данных даёт до 4 символов на байт. Ввод понимает оба формата.

### `extra_float_digits = 3`

- **Влияет на:** вывод `float4` / `float8`.
- **Почему 3:** на PG12+ любое значение больше 0 даёт кратчайшее точное представление (round-trip), а 0 и меньше — округлённый вывод (15 / 6 значащих цифр). При округлении разные значения печатаются одинаково, и расхождение пропускается. 3 — максимум, точный вывод на всех версиях, pg_dump использует его же. Ложное расхождение появится, если на одной ноде в `postgresql.conf` стоит 0.

### `lc_monetary = 'C'`

- **Влияет на:** вывод `money`: символ валюты, разделители и **число знаков после запятой**. `money` хранит целое в младших единицах, масштаб при выводе берётся из локали: одно и то же `100` печатается как `$1.00` в `C` и как `¥100` в `ja_JP`.
- **Почему C:** эта локаль есть на любой системе; другую можно не суметь задать, если её нет на ноде (ошибка при подключении). Вывод в `C` фиксированный: `$1,000.00`.

### `search_path = pg_catalog`

- **Влияет на:** вывод reg*-типов: `regclass`, `regtype`, `regproc`, `regprocedure`, `regoper`, `regoperator`, `regconfig`, `regdictionary`, `regcollation`. Имя квалифицируется схемой, только если объект не виден через `search_path`: колонка `regclass` даст `t` на одной ноде и `public.t` на другой. На `regnamespace` и `regrole` не влияет.
- **Почему pg_catalog:** ни один пользовательский объект не виден без схемы, всё печатается квалифицированно на обеих нодах. Пустой `search_path` дал бы то же, но `pg_catalog` явнее.
- **Риск:** все SQL-запросы ACE должны квалифицировать схемой пользовательские таблицы и свои вспомогательные функции (см. комментарий про `bytea_xor` в `merkle.go`). Проверить до включения.

### `quote_all_identifiers = off`

- **Влияет на:** кавычки в выводе reg*-типов и в `format_type` / `pg_get_*` (`"t"` или `t`).
- **Почему off:** значение по умолчанию. Важно не само значение, а совпадение. Фиксировать на случай, если в `postgresql.conf` одной ноды его включили. В collect.go его нет — добавить туда тоже.

## Группа 1а. На хэш не влияют, но нужны для repair

### `standard_conforming_strings = on`

- **Влияет на:** разбор строковых литералов в SQL, который строит ACE. При `off` обратный слэш в `'...'` становится escape-символом, и repair запишет другое значение. На вывод не влияет.
- **Почему on:** значение по умолчанию с 9.1; литерал значит ровно то, что в нём написано. Лучше всего передавать значения параметрами (`$1`) — тогда параметр не важен.

### `xmloption = content`

- **Влияет на:** разбор ввода `xml`. При `document` вставка фрагмента завершится ошибкой. На вывод не влияет.
- **Почему content:** значение по умолчанию; принимает и фрагменты, и документы (с PG16 — и с DOCTYPE).

### `client_encoding = UTF8`

pgx задаёт его сам. Это кодировка, в которой Go получает значения для построчного сравнения.

## Группа 2. Нельзя зафиксировать в сессии: снимок и проверка до сравнения

`mtree build` сохраняет снимок рядом с границами. Diff сравнивает снимки до работы с данными, по умолчанию останавливается, а с `--ignore-node-settings-mismatch` продолжает и пишет предупреждение в начало отчёта.

### Major version PostgreSQL (`server_version_num / 10000`)

- **Влияет на:** вывод отдельных типов между версиями (например, float в PG12) и набор функций (`trim_scale` — с PG13).
- **Почему только major:** политика проекта запрещает менять формат вывода в минорных релизах. Сравнение минорных версий дало бы ложные остановки при rolling-обновлении.

### Collation колонок PK

Для каждой колонки PK collatable-типа (включая домены, массивы и composite над ними):

- провайдер (`libc` / `icu` / `builtin`), имя, `collversion` и `pg_collation_actual_version()`; для collation по умолчанию — `datcollversion`;
- признак deterministic.

- **Влияет на:** порядок ключей, то есть границы диапазонов. Строка попадает в разные блоки на разных нодах, блоки ложно расходятся. При nondeterministic collation меняется само равенство ключей (`'A' = 'a'`). Для PK из `int` / `uuid` / `timestamp` проверка не нужна.
- **Почему с версией:** одно имя `en_US.UTF-8` на glibc 2.27 и 2.28 сортирует по-разному. Версию ICU или glibc видно только через `collversion`.

### Порядок значений enum в PK

- **Влияет на:** порядок ключей. Сортировка идёт по `enumsortorder`, а не по тексту; при разных `ADD VALUE BEFORE/AFTER` порядок на нодах различается.
- **Что сохранять:** список меток в порядке `enumsortorder`.

### Нестандартный btree opclass у индекса PK

- **Влияет на:** порядок ключей, как collation.
- **Что сохранять:** имя opclass и версию расширения, которое его даёт.

### Версии расширений, чьи типы есть в колонках таблицы

- **Что сохранять:** `pg_extension.extversion`; для PostGIS ещё `postgis_lib_version()` — библиотека и SQL-часть обновляются раздельно.
- **Влияет на:** вывод этих типов, который может меняться между версиями.

### `server_encoding`

- Только как информация, кроме одного случая: **`SQL_ASCII` — останавливаться**.
- **Почему:** `convert_to(..., 'UTF8')` выравнивает кодировки, поэтому LATIN1 и UTF8 дают одинаковый хэш. Но из `SQL_ASCII` конвертация не выполняется, байты идут как есть: LATIN1-байты на такой ноде и те же символы в UTF8 на другой дадут разные хэши.

## Группа 3. Структурные предусловия (должен пройти schema-diff)

Это не настройки, но при их нарушении каждая строка ложно попадает в diff:

- **Порядок атрибутов composite-типа.** `record_out` печатает их в порядке каталога своей ноды. Дыры в attnum не мешают, разный порядок мешает.
- **Типы колонок.** `timestamp` и `timestamptz` печатаются по-разному. `numeric(10,2)` и `numeric` сравниваются нормально (`trim_scale`), домен над `numeric` — нет (см. `isNumericType`).
- **Метки enum.**

Порядок запуска: сначала schema-diff, потом data-diff.

## Группа 4. Не настройки, но выглядит как ложное расхождение

- **Разный момент снимка на нодах:** транзакции в работе и лаг репликации. Исчезают при повторном запуске.
- **Отставание CDC-слота:** дерево mtree отражает прошлое состояние.
- **Stored generated columns** с функциями, объявленными `IMMUTABLE`, но зависящими от GUC. До PG18 они вычисляются на подписчике: значения различаются по-настоящему, но причина в конфигурации, а не в потере данных.

## Что точно не влияет

- `lc_numeric`, `lc_time` — только `to_char`;
- `timezone_abbreviations` — только ввод; в UTC аббревиатур в выводе нет;
- `lc_collate` / `lc_ctype` для колонок не из PK — хэш считается по байтам текста;
- `default_toast_compression`;
- минорная версия PostgreSQL.
